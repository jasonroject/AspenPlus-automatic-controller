# Aspen Plus 自动化控制使用指南

[返回项目首页](../README.md)

文中所有命令均在项目根目录 `automatic/` 执行，代码和数据路径也相对于该目录。

## 环境与启动

网页版需要 Windows、已安装并可正常打开的 Aspen Plus、Python 3 和 pywin32，以及浏览器。“浏览本机文件”按钮和桌面版需要 Tkinter（Windows 的常规 Python 安装通常已包含）。

双击项目根目录的 [启动网页版.bat](../启动网页版.bat)。启动后浏览器会打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)，使用期间保留启动窗口。

手动启动：

```powershell
python -m pip install pywin32
python -X utf8 web_server.py
```

也可使用 `py -3 -X utf8 web_server.py`。需要换端口或自行打开浏览器时：

```powershell
python -X utf8 web_server.py --port 8766 --no-browser
```

此时访问 `http://127.0.0.1:8766`。服务默认只在本机监听，网页和 Aspen 都运行在当前电脑上。直接双击 `web/index.html` 无法调用 Aspen，必须通过启动脚本或上面的命令运行本机服务。

点击模型路径旁的“浏览本机文件”，会打开系统文件选择窗口，选中 `.bkp` 后自动回填完整路径，再点击“读取模型参数”。取消选择不会改动现有路径或工况表；运行和参数读取期间该按钮不可用。

### 更新已有安装

1. 等待当前计算结束，或点击“完成当前行后停止”并等其结束。保存当前方案，下载需要的结果；重启后旧页面的结果下载链接会失效，已保存的本机输出文件仍保留。
2. 关闭旧的网页版启动窗口。在项目根目录执行下面的命令更新代码，也可以在 VS Code 中拉取。如果 Git 提示存在冲突或本地修改，先保留并处理这些修改，不要强制覆盖。

   ```powershell
   git pull --ff-only
   ```

3. 重新双击 `启动网页版.bat`，再在网页按 `Ctrl + F5` 刷新。浏览器会恢复已保存的草稿，也可以通过“导入方案”恢复 JSON 文件。

网页文件和 Python 后台分别加载：只刷新网页，或在旧服务还开着时再次双击启动脚本，都不会更新后台代码。新增按钮提示“接口不存在”或“当前运行的本机服务尚未更新”时，按上述步骤重启即可。

## 行和列分别代表什么

- **一行 = 一次 Aspen 运行。** 有几行就运行几次，按从上到下的顺序执行。
- **一列 = 一个要设置的参数。** 同一行可以同时填写反应器温度、泵压力、进料温度等不同设备的参数。
- 同一行的参数会在计算前一起写入；不同运行行依次计算。
- **空白单元格 = 沿用原始模型值。** 整行参数都留空时，仍会按原始模型运行一次，不跳过，也不继承上一行的计算结果。

| 运行名称 | REACTOR · 反应温度 [K] | HEATER · 温度设定 [K] | PUMP · 压力设定 [MPa] |
|---|---:|---:|---:|
| 原模型基准 | | | |
| 工况 A | 603 | 603 | 25 |
| 工况 B | 608 | 608 | 24 |

这张表包含 **3 次运行、3 个参数列**。

## 网页版：从模型到运行结果

1. **选择模型。** 从本机模型列表中选择 `.bkp`，或点击“浏览本机文件”选取模型，完整路径会自动填入。也可手动输入路径；文件须位于运行服务的当前电脑上。
2. **读取模型参数。** 点击同名按钮，等待网页读取设备及物流的输入目录。参数值使用模型原生单位，填写前先核对单位和模型原值。
3. **添加参数列。** 每列对应一个设备或物流参数。可以同时加入反应器温度、泵压力、进料温度等不同设备的变量。
4. **添加运行行并填写数值。** 一行运行一次，同一行的参数在计算前一起写入。空白格沿用原模型；全空行也是一次基准运行。
5. **开始运行。** 所有行依次执行，观察每行状态及运行日志。计算过程中可请求停止，程序在当前行结束后停止后续行。
6. **查看结果。** 在“运行与结果”查看各行数据，展开“全部流股组分”中的流股查看全部组分。点击“下载汇总 CSV”获取含全部组分质量流量列的汇总，或点击“下载全部组分 CSV”获取逐运行、逐流股、逐子物流的明细；详细 JSON、设备/物流 CSV 和批次配置保存在本机输出目录。

**“同一行多个变量”不表示同时启动多个 Aspen。** 程序先设置这一行填写的全部参数，再运行一次；完成这一行后再运行下一行。每行重新载入原模型，不继承上一行的计算结果。

本机已有五参数示例配置时，可点击“试用已有方案”载入；也可以用“导入方案”打开自己保存的运行表 JSON。“保存方案”将模型、参数目录、列顺序、空白行和填写数值保存为 JSON。新增模型配置不随源码分发，新用户应先读取自己的模型。导入只恢复运行计划，不会自动开始计算，也不会执行 JSON 中的 Python 控制脚本。导入后先检查模型路径；更换模型或模型内容变化后重新读取参数，避免使用旧参数目录。运行时还会检查实际节点及参数回读值。

网页会在当前浏览器自动保存草稿，刷新后可继续编辑。点击“保存方案”还会在 `generated/web-plans/` 留存 JSON，并开始浏览器下载；需要长期保留或交给其他电脑使用时，请保存方案文件。网页版单份计划最多 5,000 行，计算仍按行依次执行。

“执行完成”表示计算调用和结果保存流程完成；仍需核对 Aspen 收敛情况和结果合理性。左侧“使用指引”和工况表右上角“怎样填写？”可以随时重新打开说明。

### 网页版的省时操作

- **搜索参数**：在“添加参数列”中按名称搜索，或按设备、物流筛选；可以一次勾选多列。“常用参数”用于缩小列表，未知含义的参数保留 Aspen 原名。
- **整列填值**：点击参数表头，输入统一值；留空恢复为原模型值。
- **复制与删除行**：先勾选目标行，再点击“复制行”或“删除行”。
- **Excel 粘贴**：从 Excel 复制数值区域，粘贴到目标单元格；先添加需要的参数列。“复制表格”可将表中数据复制出去。
- **批量生成行**：点击“批量生成行”，选择要变化的参数。可填 `600, 610, 620`，或用 `600:620:10` 表示“起点:终点:步长”。“逐行配对”将对应取值配成一行；“所有组合”遍历所有取值组合。其他参数可沿用指定行或原模型，预览次数后再生成，新增行追加到末尾。

批次输出中的 `web_run_plan.json` 保留完整的网页运行计划，包括停止后尚未执行的行；需要继续编辑计划时可通过“导入方案”重新打开。

### 全部流股与组分输出

| 文件 | 内容 |
|---|---|
| 单次 `results.json` | 全部设备、流股、模型组分、实际子物流、原始读数、单位和提取状态 |
| 单次 `streams.csv` | 每流股一行；温度、压力、总质量/摩尔流量及全部组分质量流量列 |
| 单次 `stream_components.csv` | 每个流股/子物流/组分一行；质量流量 kg/h、摩尔流量 kmol/h、质量/摩尔分率 |
| 批次 `batch_summary.csv` | 每运行一行；包含各流股所有组分质量流量列 |
| 批次 `batch_stream_components.csv` | 完整组分明细，加上运行序号、名称和状态；对应“下载全部组分 CSV” |

`TOTAL` 行表示各物料子物流的合计；其下的 `MIXED`、`CISOLID`、`NC` 等子物流名称以模型实际输出为准。统计时选择 `TOTAL` 或子物流明细其中一层，避免重复求和。质量/摩尔分率的分母按对应物流或子物流区分，多子物流合计分率由其合计流量计算。

没有含量筛选阈值，也不固定保留六位小数。0 表示 Aspen 返回零值；空白（网页显示 —）表示没有返回该数值，不自动补零。非传统组分等可能没有可定义或可读取的摩尔流量/摩尔分率，相关单元格保持空白。未识别的组分单位保留于 JSON 的原始读数和 `extraction_warnings`，相应换算值为空。无组分输出的热量/功等流股也保留在导出中。

旧导出文件不会自动补齐，需要用新版重新导出相应工况。更新后按“更新已有安装”重启后台并刷新网页。

## 桌面版：保留的操作入口

双击 [启动批处理GUI.bat](../启动批处理GUI.bat)，或运行 `python -X utf8 batch_gui.py`。下面的快捷键、范围生成、Excel 粘贴和菜单名称针对桌面版。

1. 双击 `启动批处理GUI.bat`，点击 **打开 Aspen 模型…**，选择 `.bkp`；也可“打开运行表…”载入已有 JSON。
2. 点击 **添加参数列…**。搜索中文名称、设备名或 Aspen 原名，可跨设备一次选择多列，点击“添加所选列”。首次加列时自动创建第一行。
3. 点击 **添加运行行** 增加运行次数；或“复制选中行”复制数值后修改。
4. 双击单元格输入值。`Tab` 移到下一格，`Enter` 移到下一行同一列，`Esc` 取消当前编辑。
5. 点击 **开始运行全部 N 行**。每行显示“等待中 / 运行中 / 已导出 / 失败”；日志和进度条显示执行情况。
6. 完成后“打开结果文件夹”。“已导出”表示程序完成了计算调用和结果保存，并非自动认证模型收敛。

主界面始终显示运行行数和参数列数。旧版控制脚本入口收在“更多 → 从旧版控制脚本导入…”。

### 参数列操作

- **添加参数列…**：选择需要修改的参数；已存在的参数和同一节点的别名不会重复添加。新增格子留空，保留原模型设置。
- **删除当前列**：先点击列标题，再删除；保留运行行和其他列。
- **整列填值…**：先点击列标题，再输入统一值，填入所有行；输入空白可清除整列设定。
- 点击参数标题或单元格可查看模型原值、单位、稳定参数标识和原始 Aspen 路径。
- `Ctrl` / `Shift` 选择多行；`Delete` 清空当前列在选中行中的单元格，不会删除整行。

参数选择窗口默认显示常用参数，取消“仅显示常用参数”可查看全部输入候选。搜索会查询全部候选，支持中文名及 Aspen 原名。未确定含义的字段保留原名；例如“规格值”随设备规格方式解释，“组分输入值”可能是比例或流量，不直接认定为组分流量。单位未提供时显示“待核对”，不猜测单位。

### 按范围生成多行

先添加想控制的参数列，再点击 **按范围生成多行…**：

1. 选择一列，填写逗号分隔的取值，点击“加入取值列表”。也可输入起始、终止、点数，生成等间隔取值。
2. 为其他需要变化的列加入取值。
3. 选择生成方式，查看新增行数预览，点击“添加到运行表”。

- **逐行配对**：两列各有两个值，配成两行；只有一个值的参数会固定用于每行。
- **所有组合**：两种温度 × 三种压力，生成六行。
- 未设置取值的其他列沿用当前选中行；无选中行时沿用原模型。
- 生成的行追加到已有表格末尾，原行保留；单次最多新增 10,000 行。

### Excel 表格与配置

可先用“复制选中行到 Excel”生成带中文表头的模板，再在 Excel 填写并粘回。表头第一列为“运行名称”，其他列支持界面名称及单位，也兼容完整参数键。选中目标行后 Ctrl+V；未选中行则追加。无表头时从当前单元格开始粘贴，超过现有列数会提示先加列，不会静默丢失数据。

“保存运行表…”将模型路径、参数目录、列顺序和全部运行行存为 JSON；“打开运行表…”可恢复。空白行和全空白的参数列也会保留。新配置无需专用控制脚本，也可用 `python -X utf8 batch_runner.py run 配置.json` 执行。旧控制脚本和旧配置仍可加载，但旧脚本仅包含原先少量参数；要扩展范围，请重新打开 `.bkp`。

批处理保存详细 JSON、设备/物流 CSV，以及批次汇总 JSON/CSV 和可重新运行的 `batch_config.json`。参数回读值保存在汇总中的 `applied_parameters`。测试记录单独位于 `validation/`。

## 当前边界

- 扫描的是设备和物流 Input 下已有值的标量叶节点，包括嵌套的进料组分节点。它们是候选输入，不代表每个节点在任何规格模式下都可写或有效；未赋值节点和其他数据树分支尚不自动开放。
- 常见参数显示中文名称，稳定标识和 Aspen 原名在详情中保留，以便准确对应。某些规格需要连同模式参数一起修改。
- 未知参数、无效数值、写入失败、回读不一致会让当前工况失败，不继续计算该组。
- 停止会等待当前工况结束，再停止后续工况并保存结果。
- 运行成功表示控制和导出流程完成；模型收敛与物理合理性仍需要核查，当前尚无通用收敛判定。

## 结果单位修正（2026-09-26）

新导出根据每个节点的 `UnitString` 转换，JSON 同时保留 `source_quantities` 中的原始数值和单位。无法识别的单位会报错，不再默默套用固定系数。新的单次结果带有 `unit_conversion: node-unit-aware-v1` 标识。

本机热回收模型实测：进料原始流量为 100 kg/hr；旧程序乘 3600 后显示 360000 kg/h。加热器热负荷节点为 cal/sec，旧程序按 W 除以 1000。历史输出未改写，因此新旧结果不能直接混用；建议需要用于分析的旧工况重新导出。

已有 `generated/*_control.py` 中的控制台打印仍属于旧版逻辑；网页版、桌面版及批处理导出以 `test_datacatch.py` 的实际单位换算为准。

若本机保留了 `generated/heatrecovery_multi_device_example.json` 及其对应模型，可在网页版载入示例，或在桌面版用“打开运行表…”载入该文件。其他电脑请使用自己保存的方案。载入配置不会自动计算。

## 命令行与代码调用

执行 GUI 保存的配置，或执行随项目提供的示例：

```powershell
python -X utf8 batch_runner.py run generated/heatrecovery_multi_device_example.json
```

保留的传统脚本流程如下。扫描和生成模板会写入 `generated/` 中的对应文件；已有手工修改时，应先备份相应脚本或配置。

```powershell
python -X utf8 test_aspen_control.py "C:/path/to/model.bkp"
python -X utf8 batch_runner.py generate-template generated/model_control.py
# 编辑生成的配置，填写 parameter_sets 后运行
python -X utf8 batch_runner.py run generated/model_batch_config.json
```

传统参数键为 `设备名.中文参数名`，新扫描键为 `Blocks.设备名.节点路径` 或 `Streams.物流名.节点路径`。应使用当前配置中实际存在的键，避免用两个别名重复设置同一节点。

代码调用可复用 GUI 保存的新配置：

```python
import json
from pathlib import Path
from batch_runner import BatchRunner

config = json.loads(Path("generated/heatrecovery_multi_device_example.json").read_text(encoding="utf-8"))
runner = BatchRunner(Path(config["model_path"]), {}, [], config["parameter_catalog"])
cases = config["parameter_sets"]
runner.run_batch([case["parameters"] for case in cases],
                 [case.get("_name") for case in cases])
runner.save_batch_summary()
```

单变量、全组合及自定义工况的传统代码示例保留在 [batch_example.py](../batch_example.py)。

## 启动与运行排错

- **双击窗口立即关闭**：在项目根目录打开 PowerShell，执行 `python -X utf8 web_server.py` 查看错误；桌面版用 `python -X utf8 batch_gui.py`。
- **浏览器无法连接本机服务**：确认启动窗口仍开着，地址和启动端口一致。请通过 `http://127.0.0.1:8765` 访问，而不是直接打开 HTML 文件。
- **浏览文件提示“接口不存在”或“本机服务尚未更新”**：后台仍是旧版本。按[更新已有安装](#更新已有安装)关闭旧服务、重新启动并刷新网页。
- **提示“页面会话已失效”**：服务重启后需要刷新网页，让页面重新连接当前服务。
- **点击浏览后显示“等待选择文件…”**：请在系统文件选择窗口中选取 `.bkp` 或取消；检查该窗口是否被其他窗口遮挡。
- **端口已占用**：用 `python -X utf8 web_server.py --port 8766` 启动，再访问新的端口。
- **找不到 Python**：执行 `Get-Command python, py -ErrorAction SilentlyContinue` 检查可用命令；可改用 `py -3`，或用 `& "C:/实际路径/python.exe" -X utf8 web_server.py` 指定解释器。
- **缺少 pywin32**：用启动程序的同一个解释器执行 `python -m pip install pywin32`。
- **文件选择窗口或桌面版缺少 tkinter**：先用 `python -c "import tkinter"` 检查；安装或修复含 Tcl/Tk 的 Python。网页也可手动填写模型路径继续使用。
- **模型不在列表中**：点击“浏览本机文件”选择 `.bkp`，或填写完整路径，并确认文件在当前电脑上存在。
- **COM 无法连接**：确认 Aspen Plus 可以手动启动、授权有效，且安装已注册 `Apwn.Document`。
- **未知参数或节点不存在**：重新打开当前模型，检查表头是否属于该模型。
- **写入失败或回读不一致**：检查参数单位、输入类型及设备规格模式；这类工况不会继续计算。
- **计算失败或导出单位无法识别**：查看该组 `error` / `traceback`，结合 Aspen 自身状态排查；不能把失败结果当作有效工况。

## 验证命令

不启动 Aspen 的回归测试：

```powershell
python -X utf8 -m unittest test_parameter_control test_gui_control test_web_server -v
python -X utf8 test_batch_runner.py
```

真实 Aspen 集成验证：

```powershell
python -X utf8 validate_live_aspen.py
```

该命令会真实运行热回收模型两次，依赖本机模型及 `validation/heatrecovery_catalog.json`，输出单独放入 `validation/`。这些模型数据和实测附件不随源码分发；没有相应文件时仅运行上面的自动化回归测试。
